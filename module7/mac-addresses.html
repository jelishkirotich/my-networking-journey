MODULE 7

MAC Addresses

Learn what MAC addresses are, how they are written, what their different parts mean, the different types of MAC addresses, and how Ethernet switches use them to forward frames.

1. What Is a MAC Address?

A MAC address is a Layer 2 address used by Ethernet networks to identify a network interface.

MAC stands for Media Access Control.

When a device communicates over an Ethernet network, Ethernet frames contain a source MAC address and a destination MAC address.

Simple definition

A MAC address is an address associated with a network interface and used for communication at the Data Link Layer.

MAC addresses are especially important to Ethernet switches because switches use them to determine where Ethernet frames should be forwarded.

2. Why Do We Need MAC Addresses?

Imagine a classroom containing many students.

If a teacher wants to give a message to one particular student, simply saying "someone in this classroom" would not be enough.

The teacher needs some way to identify the intended student.

Similarly, a switch may have many devices connected to it. It needs a way to identify the network interfaces associated with those devices.

PC0 |

PC1 | Switch | PC2

| PC3

The switch can use MAC addresses to distinguish between the different network interfaces.

3. A Traditional Ethernet MAC Address Is 48 Bits

A traditional Ethernet MAC address is 48 bits long.

A bit can have one of two values:

0 or 1

Therefore, a 48-bit MAC address contains 48 binary digits.

Writing all 48 bits every time would be inconvenient, so MAC addresses are normally written using hexadecimal.

4. Why Are MAC Addresses Written in Hexadecimal?

Hexadecimal, or hex, is a number system that uses 16 symbols.

One hexadecimal digit represents exactly 4 binary bits.

1 hexadecimal digit = 4 bits

2 hexadecimal digits = 8 bits = 1 byte

12 hexadecimal digits = 48 bits = 6 bytes

That is why a 48-bit MAC address can conveniently be written using 12 hexadecimal digits.

There are six groups, each containing two hexadecimal digits.

6. Parts of a Traditional MAC Address

You may hear that a MAC address is divided into two major portions:

  • A manufacturer-related portion
  • An interface-specific portion

The first 24 bits are traditionally associated with an organizational identifier called an OUI (Organizationally Unique Identifier).

The remaining 24 bits are used within the assigned address block.

48-bit MAC Address

↓

First 24 bits | Last 24 bits

Organizational identifier | Interface/address portion

Important modern clarification

Do not assume that every MAC address is simply a permanent manufacturer serial number.

Ethernet supports different address types, including locally administered addresses, and modern systems can use addresses that are not simply the original manufacturer-assigned value.

7. Unicast MAC Address

A unicast transmission is intended for one specific destination.

For example:

PC0 → Switch → PC1

Only PC1 is the intended destination.

The Ethernet frame contains PC1's MAC address as the destination MAC address.

If the switch knows which port leads to PC1, it can forward the frame specifically to that port.

Remember

Unicast = one intended destination.

8. Broadcast MAC Address

A broadcast transmission is intended for all devices within the relevant Layer 2 broadcast domain.

The Ethernet broadcast MAC address is:

FF:FF:FF:FF:FF:FF

This special destination address tells Ethernet devices that the frame is broadcast traffic.

↓

Switch

↙ ↓ ↘

PC1    PC2    PC3

The switch floods a broadcast frame within the relevant broadcast domain, except back out the port where it arrived.

Example: ARP

Address Resolution Protocol (ARP) requests commonly use an Ethernet broadcast because the sender is trying to discover which device owns a particular IPv4 address.

9. Multicast MAC Address

A multicast transmission is intended for a group of devices rather than exactly one device or every device.

Sender

↓

Switch

↙ ↓ ↘

Device A   Device B   Device C

Members of the multicast group

Multicast is useful when one source needs to communicate with multiple interested receivers.

Switches can use additional mechanisms, such as multicast snooping, to handle multicast traffic more efficiently.

Remember

Unicast = one

Multicast = selected group

Broadcast = everyone in the broadcast domain

11. Universally vs Locally Administered MAC Addresses

MAC address terminology can become confusing here, so let's keep it simple.

A MAC address can indicate whether it is universally administered or locally administered.

A universally administered address is assigned according to the relevant organizational address-allocation system.

A locally administered address is intended to be administered locally rather than treated as a globally assigned hardware address.

Why should you care?

This is one reason why saying "every MAC address is permanently unique and cannot change" is too simplistic.

The important beginner concept is that MAC addresses are Layer 2 addresses associated with network interfaces and used in Ethernet communication.

12. How Does a Switch Use MAC Addresses?

This is one of the most important sections in this module.

An Ethernet switch maintains a MAC address table.

The table associates learned MAC addresses with the switch ports through which those addresses were observed.

For example:

MAC Address Port
00:11:22:33:44:55 Fa0/1
00:AA:BB:CC:DD:EE Fa0/2

Cisco documentation describes MAC learning as a process where the switch examines the source MAC of a received frame and associates it with the incoming interface and VLAN.

13. Why Does the Switch Learn the Source MAC?

This question is extremely important.

Suppose PC0 sends a frame into the switch.

PC0

↓

Switch Port Fa0/1

The switch sees:

  • The frame came through Fa0/1.
  • The source MAC is PC0's MAC address.

Therefore, the switch can safely conclude:

PC0 MAC → Fa0/1

This is useful information because the switch now knows which port can be used to reach PC0.

14. Why Doesn't the Switch Learn the Destination MAC From the Frame?

The switch can absolutely read the destination MAC address.

The issue is not that the destination MAC is invisible.

The issue is that the destination MAC does not tell the switch which port that destination is connected to.

Think carefully about the information available

The switch receives a frame through a particular port.

Therefore:

Source MAC + Incoming Port

gives the switch a direct observation it can learn from.

But:

Destination MAC

only tells the switch who the frame is intended for.

It does not tell the switch which of its other ports leads to that destination.

The switch therefore uses the destination MAC to look up a port rather than learning the destination-port relationship from that field.

15. Example: PC0 Sends to PC1

Imagine this network:

16. What If the Destination MAC Is Unknown?

Now imagine the switch receives a frame whose destination MAC address is not currently in its MAC address table.

The switch knows:

  • The source MAC address
  • The port where the frame arrived
  • The destination MAC address written in the frame

But it does not know which port leads to the destination MAC.

In the case of an unknown unicast, the switch floods the frame out the relevant ports in the same VLAN, except the port on which the frame arrived.

PC0

↓

Switch

↙ ↓ ↘

PC1    PC2    PC3

The destination device receives the frame and can respond.

When the response comes back, the switch sees that device's MAC address as a source MAC.

The switch can then learn the destination device's MAC and associate it with the port where the response arrived.

This is how the switch gradually builds its MAC address table.

17. How a Switch Builds Its MAC Address Table

MAC address learning happens dynamically as frames arrive.

Frame arrives

↓

Switch examines source MAC

↓

Switch sees incoming port

↓

MAC + Port relationship is learned

↓

Entry stored in MAC address table

Cisco documentation describes dynamic MAC entries as learned from received traffic and notes that inactive entries can eventually age out of the table.

18. What Is MAC Address Aging?

A switch should not keep an old MAC address-to-port relationship forever.

Imagine that a laptop was connected to Port 3 yesterday but today it has been moved to Port 7.

If the switch permanently kept:

Laptop MAC → Port 3

it could make incorrect forwarding decisions.

Dynamic MAC table entries therefore have an aging mechanism. If an address is not observed for the relevant period, the entry can be removed and learned again when traffic appears.

19. Dynamic vs Static MAC Entries

Dynamic Static
Learned automatically from received frames. Configured manually or through a specific feature.
Can age out when no longer used. Does not behave like an ordinary dynamically learned entry.
Common for normal end-device learning. Used when an administrator wants a specific configured behavior.

Cisco switch documentation distinguishes dynamic and static MAC entries in the MAC address table.

20. MAC Address vs IP Address

This is one of the most important distinctions in networking.

MAC Address IP Address
Used primarily at Layer 2. Used at Layer 3.
Used for local frame delivery. Used for logical addressing and routing between networks.
Traditionally 48 bits for Ethernet. IPv4 is 32 bits; IPv6 is 128 bits.
Written in hexadecimal. IPv4 is commonly written in dotted decimal.

Do not mix them up

An IP address answers a different networking question from a MAC address.

MAC address → Layer 2 local delivery

IP address → Layer 3 logical addressing and routing

23. MAC Addresses: Summary

A MAC address is a Layer 2 address associated with a network interface.

Traditional Ethernet MAC addresses are 48 bits long and are commonly written as hexadecimal values.

Ethernet uses MAC addresses in frames to identify the source and destination of local network traffic.

Switches learn source MAC addresses by observing the frames that arrive on their ports. They then use the learned MAC-to-port mappings to make forwarding decisions.

The most important idea

Source MAC → used for learning.

Destination MAC → used for forwarding lookup.
