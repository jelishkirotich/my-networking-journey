MODULE 7

Encapsulation

Learn how data is prepared for transmission as it moves down the network layers, and how the receiving device reverses the process.

```

1. What Is Encapsulation?

Encapsulation is the process of adding networking information to data as it moves down through the layers of a protocol stack before it is transmitted across a network.

A computer does not simply take an application message and put it directly onto a network cable. The data needs additional information so that the network knows how to transport it, where it should go, and how different devices should process it.

Each layer adds information that is relevant to its own job. Usually, this information is placed in a header. At the Data Link layer, Ethernet can also add a trailer containing the Frame Check Sequence (FCS).

Simple Definition

Encapsulation = adding information to data as it moves down the network layers.

Cisco describes encapsulation as adding headers at each layer of the protocol stack. When the data reaches the receiving device, those headers are removed in reverse order.

2. Why Do We Need Encapsulation?

Imagine that PC0 wants to send a message to PC1.

The original message might simply be:

"Hello PC1"

But the network needs much more information than the message itself. For example:

  • Which application should receive the data?
  • Which transport protocol is being used?
  • What is the source IP address?
  • What is the destination IP address?
  • What is the source MAC address?
  • What is the destination MAC address?
  • Has the frame been damaged during transmission?

Different layers are responsible for different parts of this information.

Encapsulation allows each layer to add the information it needs without requiring one layer to perform every networking task.

3. The Encapsulation Process

The easiest way to understand encapsulation is to follow data from the sending computer downward through the layers.

4. Step 1 — Application Data

The process begins at the application side of the computer.

For example, imagine that you are using a web browser and sending information to a web server.

The application produces information that needs to travel through the network.

At this stage:

The information is simply referred to as data.

At this point, we have not yet added the Ethernet frame or IP header.

5. Step 2 — Transport Layer

The data moves down to the Transport layer.

The Transport layer can use protocols such as:

  • TCP — Transmission Control Protocol
  • UDP — User Datagram Protocol

The transport protocol adds its own information to the application data.

With TCP, this can include information such as source and destination port numbers, sequence information, and other TCP control information.

With UDP, the transport header is simpler and includes information such as source and destination ports.

Result

Application data + Transport header = Segment when TCP is used.

With UDP, the PDU is commonly called a datagram.

6. Step 3 — Network Layer

The information now moves to the Network layer.

In an IP network, the Network layer adds an IP header.

The IP header contains important information such as:

  • Source IP address
  • Destination IP address
  • Protocol information
  • Other information used for delivering the packet

The IP addresses help the network identify the source and destination at the logical addressing level.

Result

Transport segment/datagram + IP header = IP packet.

This is different from a MAC address. IP addressing belongs to the Network layer, while Ethernet MAC addressing is part of the Data Link layer.

7. Step 4 — Data Link Layer

The packet now moves to the Data Link layer.

Because this module focuses heavily on Ethernet, we can think of an Ethernet network at this stage.

Ethernet adds information such as:

  • Destination MAC address
  • Source MAC address
  • EtherType or Length information
  • Frame Check Sequence (FCS)

The IP packet becomes the payload carried inside the Ethernet frame.

Inside the Ethernet Frame

Result

IP packet + Ethernet information = Ethernet frame.

Ethernet frames contain addressing and control information around the data they carry. The FCS is used by the receiving device to check whether the frame was damaged during transmission.

8. Step 5 — Physical Layer

The completed frame is passed to the Physical layer.

The Physical layer is responsible for transmitting the information across the physical medium.

Depending on the technology, this can involve electrical signals, light pulses, or radio signals.

At the conceptual level, we often describe the information at this stage as bits.

The Result

The Ethernet frame is converted into a form that can travel across the physical network medium.

10. What Happens at the Destination? — Decapsulation

Encapsulation happens at the sending device.

The receiving device performs the reverse process, called decapsulation.

Decapsulation means that the receiving device processes and removes the relevant headers and trailer as the information moves upward through the protocol stack.

Cisco describes this as the encapsulation headers being removed in reverse order as the packet moves up the receiving protocol stack.

Physical Layer

Bits/signals

↓

↓

↓

Network Layer

IP information is processed

↓

Transport Layer

TCP/UDP information is processed

↓

Application

Original data is delivered to the appropriate application

11. A Simple Letter Analogy

Think about sending a physical letter.

You first write the actual message.

Then you put the message inside an envelope.

You write the destination information on the envelope so that the postal system knows where to send it.

The postal system may then use additional information while transporting the envelope.

Networking works in a similar layered way.

Networking Letter Analogy
Application data The actual message
Transport information Additional delivery instructions
IP information Logical destination information
Ethernet frame Envelope carrying the message
Bits/signals The physical process of transporting it

Important

The analogy helps you understand the idea, but networking is more precise and complex than sending a physical letter.

12. PC0 → Switch → PC1

Now connect encapsulation to what you have already learned about Ethernet and switches.

Suppose PC0 wants to send data to PC1 on the same Ethernet network.

At PC0

  1. The application creates data.
  2. The Transport layer adds transport information.
  3. The Network layer adds IP information.
  4. The Data Link layer creates an Ethernet frame.
  5. The frame contains source and destination MAC addresses.
  6. The Physical layer transmits the frame as signals/bits.

At the Switch

The switch receives the Ethernet frame.

The switch operates primarily at the Data Link layer for normal Ethernet switching. It examines the Ethernet frame, including the destination MAC address, and uses its MAC address table to decide where to forward the frame.

The switch does not need to remove the entire Ethernet frame and process the application data just to forward it.

Think About the Switch Like This

"I received a frame. Who is the destination MAC, and which port should I send this frame toward?"

At PC1

PC1 receives the frame and processes it.

The Ethernet information is handled at the Data Link layer. The IP information is handled at the Network layer. Transport information is then processed, and eventually the original data is delivered to the appropriate application.

13. What Does the Switch Actually Care About?

This is an important connection between encapsulation and switching.

When an Ethernet frame reaches a switch, the switch mainly needs information from the Ethernet frame to make its Layer 2 forwarding decision.

In particular, the switch looks at the:

  • Source MAC address
  • Destination MAC address

The switch can learn the source MAC address from the frame's incoming interface and associate that address with the port.

It then examines the destination MAC address to determine whether it has a matching forwarding-table entry.

Information Used by a normal Layer 2 switch?
Source MAC Yes
Destination MAC Yes
Source IP Not normally for basic Layer 2 forwarding
Destination IP Not normally for basic Layer 2 forwarding
Application message No

This is why understanding encapsulation helps you understand switching: the switch is working with the Ethernet frame at the Data Link layer rather than making its normal forwarding decision from the application data.

14. What Exactly Gets Added?

It is common to say that "each layer adds a header." This is useful for learning, but we need to be precise.

Layer Typical information added Common PDU name
Application Application data Data
Transport TCP or UDP header Segment / Datagram
Network IP header Packet
Data Link Ethernet header + FCS trailer Frame
Physical Signal representation Bits

So when people say "the layer adds information," they are talking about the control information required by that layer's protocol.

15. What Is a PDU?

You will often see the abbreviation PDU in networking.

PDU means Protocol Data Unit.

It is simply the name given to the data unit at a particular layer of the networking model.

Layer PDU
Application Data
Transport Segment / Datagram
Network Packet
Data Link Frame
Physical Bits

Do Not Mix These Up

A packet is not the same thing as a frame.

The packet is associated with the Network layer, while the frame is associated with the Data Link layer.

The packet can be carried inside the payload of an Ethernet frame.

16. Encapsulation vs Decapsulation

Encapsulation Decapsulation
Occurs at the sending side Occurs at the receiving side
Moves down the stack Moves up the stack
Information is added Information is processed and removed as appropriate
Data → Segment → Packet → Frame → Bits Bits → Frame → Packet → Segment → Data

17. Important Distinction: Encapsulation Is Not the Same as Encryption

These two terms can sound similar, but they mean very different things.

Encapsulation

Encapsulation adds protocol information around data so that the networking layers can process and transport it.

Encryption

Encryption transforms information into a protected form so that unauthorized parties cannot easily understand the original content.

Encapsulation is about organizing and carrying data.

Encryption is about protecting the confidentiality of data.

18. Key Ideas to Remember

  • Encapsulation happens as data moves down the protocol stack.
  • Each layer adds information needed by its protocol.
  • The Transport layer commonly produces a segment for TCP or a datagram for UDP.
  • The Network layer produces a packet.
  • The Data Link layer produces a frame.
  • Ethernet frames contain MAC addressing information.
  • The Physical layer transmits the information using physical signals.
  • Decapsulation reverses the process at the receiving device.
  • A switch normally makes its basic forwarding decision using Ethernet/MAC information, not the application message.

19. Quick Notes

Encapsulation: The process of adding protocol information to data as it moves down the network stack.

Decapsulation: The reverse process at the destination, where the receiving device processes and removes the relevant protocol information as data moves up the stack.

PDU: Protocol Data Unit — the name given to data at a particular network layer.

Transport: Segment (TCP) / Datagram (UDP)

Network: Packet

Data Link: Frame

Physical: Bits/signals

Encapsulation order: Data → Segment → Packet → Frame → Bits

Decapsulation order: Bits → Frame → Packet → Segment → Data

Ethernet frame: Carries the network-layer packet as its payload and includes Layer 2 information such as source and destination MAC addresses.
```
