MODULE 7

Ethernet Switches

Learn how Ethernet switches receive frames, learn MAC addresses, make forwarding decisions, and improve communication on a LAN.

```

1. What Is an Ethernet Switch?

An Ethernet switch is a networking device used to connect devices together on a local area network (LAN).

For example, a small network might contain:

  • PC0
  • PC1
  • PC2
  • A printer
  • A server
  • An Ethernet switch

Instead of connecting every computer directly to every other computer, the devices connect to the switch.

Simple LAN

PC0 ────────┐

PC1 ────────┤

PC2 ────────┼──── SWITCH

Printer ────┤

Server ─────┘

The switch receives Ethernet frames from connected devices and decides which port should receive each frame.

Simple Definition

A switch connects devices on a LAN and forwards Ethernet frames toward their destination using MAC addresses.

2. Why Do We Need a Switch?

Imagine having five computers that need to communicate.

You could theoretically connect devices directly to each other, but that would become complicated very quickly.

A switch gives the network a central point where devices can connect.

Without a Switch

Many direct connections would be required.

With a Switch

Each device connects to the switch, and the switch handles forwarding between them.

A switch also makes communication more efficient because it can learn where devices are located and forward known unicast frames toward the appropriate port instead of sending every frame everywhere.

3. What Happens When a Frame Reaches a Switch?

This is the most important process to understand.

Remember what you learned in the previous page about encapsulation.

A computer creates an Ethernet frame containing information such as:

  • Source MAC address
  • Destination MAC address
  • Type/Length information
  • Payload
  • FCS

When that frame arrives at a switch, the switch examines the Ethernet information and makes a forwarding decision.

The Basic Process

Receive → Learn → Look up destination → Forward, flood, or filter

4. Step 1 — The Switch Receives the Frame

Imagine PC0 sends an Ethernet frame.

PC0

↓

Switch Port 1

The frame enters the switch through one of its ports.

The switch knows which physical port the frame arrived on because the switch interface itself received the frame.

This incoming port is important because the switch uses it when learning the source MAC address.

5. Step 2 — The Switch Learns the Source MAC Address

This is one of the most important ideas in Ethernet switching.

When a frame arrives, the switch looks at the source MAC address.

It then associates that MAC address with the port on which the frame arrived.

For example, suppose PC0 has:

PC0 MAC = 00:11:22:33:44:55

PC0 is connected to Switch Port 1

When PC0 sends a frame, the switch can learn:

00:11:22:33:44:55 → Port 1

This information is stored in the switch's MAC address table.

Cisco documentation describes this process as dynamically building the table from the source MAC addresses of received frames and associating them with the incoming ports.

Very Important

The switch learns from the source MAC address.

It does not learn the destination MAC address simply because that address appears in the destination field.

6. Source MAC vs Destination MAC

This distinction is extremely important.

MAC Address What the Switch Does
Source MAC Learns which port the source device is reachable through.
Destination MAC Looks for a matching MAC-to-port entry to decide where to forward the frame.

Think of it this way:

Source MAC: "Where did this frame come from?"

Destination MAC: "Where does this frame need to go?"

7. The MAC Address Table

A switch maintains a table that maps MAC addresses to the ports through which those devices can be reached.

A simplified table might look like this:

MAC Address Port
00:11:22:33:44:55 Fa0/1
AA:BB:CC:DD:EE:FF Fa0/2
12:34:56:78:9A:BC Fa0/3

This means the switch has learned that a particular MAC address is reachable through a particular port.

In actual switches, the table can also contain information such as the VLAN associated with the entry.

8. What If the Destination MAC Is Known?

Suppose PC0 wants to send a frame to PC1.

Assume the switch already has this information:

PC1 MAC → Port 3

The frame arrives from PC0 through Port 1.

The switch:

  1. Receives the frame on Port 1.
  2. Examines the source MAC address.
  3. Updates or learns the source MAC-to-port mapping.
  4. Reads the destination MAC address.
  5. Looks for that destination MAC in its MAC address table.
  6. Finds the destination on Port 3.
  7. Forwards the frame out Port 3.

PC0

↓

Port 1

SWITCH

Port 3

↓

PC1

When the destination is known, the switch can send the frame toward the specific port associated with that MAC address.

This is one of the main reasons a switch is more efficient than a traditional shared Ethernet hub.

9. What If the Destination MAC Is Unknown?

Sometimes the switch receives a frame whose destination MAC address is not currently in its MAC address table.

The switch still knows the destination MAC address from the frame. What it does not know is which port leads to that destination.

In this situation, the switch performs unknown-unicast flooding.

It sends the frame out the relevant ports except the port on which the frame arrived.

PC0

↓

Port 1

SWITCH

↙ ↓ ↘

Port 2 | Port 3 | Port 4

The switch does not send the frame back out Port 1 because that is the port from which the frame came.

Cisco's switching documentation describes this behavior: if a destination MAC is not in the table, the switch forwards the unknown unicast out the other relevant ports.

10. How Does the Switch Eventually Learn That Destination?

This is where the earlier source-MAC learning concept becomes very important.

Suppose PC0 sends a frame to PC1, but the switch does not yet know which port contains PC1.

The switch floods the unknown unicast frame.

PC1 receives the frame.

When PC1 sends a response, that response contains PC1's MAC address as its source MAC address.

The switch receives that response and can now learn:

PC1 MAC → Port 3

Future frames destined for PC1 can then be forwarded directly to Port 3, assuming the entry is still valid.

This source-learning and forwarding behavior is documented by Cisco's switching material.

11. What About Broadcast Frames?

A broadcast frame is different from an unknown unicast frame.

An Ethernet broadcast uses:

FF:FF:FF:FF:FF:FF

This destination means that the frame is intended for all devices in the relevant Layer 2 broadcast domain.

A switch floods a broadcast frame out the other relevant ports within that broadcast domain, except the port on which it was received.

Cisco documentation describes broadcast and multicast frames as being flooded to the other relevant ports.

Unknown unicast: The destination is a specific device, but the switch does not currently know which port leads to it.

Broadcast: The destination is intentionally all devices in the relevant broadcast domain.

12. What Is Filtering?

A switch does not always have to forward a frame.

Imagine that a frame arrives on Port 1, and the switch's table says that the destination MAC address is also reachable through Port 1.

In that situation, sending the frame back out the same port would not make sense.

The switch can therefore filter the frame instead of forwarding it out another port.

Forward: Destination is known on another port.

Flood: Destination is unknown or the frame is broadcast/multicast, according to the relevant Layer 2 rules.

Filter: The destination is associated with the incoming port, so the frame does not need to be sent back out that same port.

13. The Three Important Switch Decisions

1. Forward

The destination MAC is known and associated with another port.

2. Flood

The destination is unknown, or the frame is a broadcast or relevant multicast frame.

3. Filter

The destination is associated with the incoming port, so forwarding it back through that same port is unnecessary.

14. Does the Switch Change the Ethernet Frame?

For normal Layer 2 switching, the switch forwards the Ethernet frame without rewriting the source and destination MAC addresses.

It examines the frame to make its forwarding decision, but it does not normally replace the original source MAC with the switch's own MAC address.

If PC0 sends a frame to PC1 through a Layer 2 switch, the frame still carries PC0's source MAC and PC1's destination MAC as it crosses the switch.

This becomes different when traffic crosses a Layer 3 boundary, such as a router, because a router creates a new Layer 2 frame for the next link.

15. Switch vs Hub

Before switches became the normal choice for Ethernet LANs, hubs were commonly used.

A hub does not make the same intelligent MAC-address forwarding decisions as a switch.

When a hub receives a signal on one port, it repeats that signal out its other ports.

Hub Switch
Repeats incoming signals Receives and forwards Ethernet frames
Does not build a MAC address table Builds a MAC address table
Does not make normal MAC-based forwarding decisions Uses destination MAC information for Layer 2 forwarding
All connected devices share the same collision domain Each switch port forms a separate collision domain in normal switched Ethernet
Generally associated with half-duplex Ethernet Modern switched Ethernet normally operates full-duplex

This is why you should not think of a modern Ethernet switch as simply a "better hub." A switch actively learns MAC-to-port information and makes forwarding decisions.

16. Complete Example: PC0 Sends to PC1

Let's put everything together.

Network

PC0 ───── Port 1

            SWITCH

PC1 ───── Port 3

Step 1 — PC0 Creates Data

An application on PC0 creates data that needs to be transmitted.

Step 2 — Encapsulation

The data moves down the protocol stack.

Transport information is added, then IP information, and then Ethernet information.

Step 3 — Ethernet Frame

PC0's NIC sends an Ethernet frame containing:

  • PC0's source MAC address
  • PC1's destination MAC address
  • The network-layer packet as the payload
  • Other Ethernet information

Step 4 — Frame Arrives at the Switch

The frame enters Port 1.

Step 5 — Switch Learns

The switch reads PC0's source MAC and learns:

PC0 MAC → Port 1

Step 6 — Destination Lookup

The switch reads PC1's destination MAC.

It checks the MAC address table.

Step 7 — Forwarding

If the table contains:

PC1 MAC → Port 3

the switch sends the frame out Port 3.

Step 8 — PC1 Receives the Frame

PC1 receives the frame and processes it through its protocol stack.

Step 9 — Decapsulation

PC1 processes the Ethernet information, IP information, transport information, and eventually delivers the original data to the appropriate application.

17. Can Multiple MAC Addresses Be Associated With One Switch Port?

Yes.

A switch port does not necessarily represent only one MAC address.

For example, if Switch 1 connects to Switch 2, many devices may exist behind the second switch.

PC0 ──┐

PC1 ──┼── Switch 2

PC2 ──┘

       │

       │

       Switch 1

From Switch 1's perspective, the port connecting it to Switch 2 can lead to multiple MAC addresses.

As frames arrive from different devices through that link, Switch 1 can learn multiple MAC addresses associated with that same outgoing port.

A MAC address table is not simply: one MAC = one switch port forever.

It represents where the switch currently knows that MAC address can be reached.

18. What Happens to Old MAC Addresses?

MAC address-table entries are not necessarily kept forever.

Dynamically learned entries can age.

If the switch does not see relevant traffic from a learned MAC address for the configured aging period, the dynamic entry can be removed.

This allows the switch to adapt when devices move, disconnect, or otherwise change their network location.

Why Is Aging Useful?

Imagine that a laptop was connected to Port 2 yesterday but is now connected to Port 5.

The switch needs a way to eventually remove stale information and learn the laptop's current location.

20. Important Terms

Term Meaning
Ethernet switch A LAN device that forwards Ethernet frames using Layer 2 information.
MAC address table A table containing learned MAC-address-to-port information.
MAC learning Learning a source MAC address and associating it with the incoming port.
Forwarding Sending a frame out the port associated with the destination MAC.
Flooding Sending a frame out multiple relevant ports, excluding the incoming port.
Filtering Not forwarding a frame when forwarding it back through the incoming port is unnecessary.
MAC aging Removal of stale dynamically learned MAC entries after the configured aging period.

21. Don't Confuse These

Source MAC vs Destination MAC

The switch learns from the source MAC.

The switch looks up the destination MAC to make a forwarding decision.

Unknown Unicast vs Broadcast

Unknown unicast: A specific destination exists, but the switch does not know which port leads to it.

Broadcast: The frame is intentionally addressed to all devices in the relevant broadcast domain.

Switch vs Router

A switch normally makes Layer 2 forwarding decisions using MAC addresses.

A router makes Layer 3 forwarding decisions using IP addressing and connects different IP networks.

22. Quick Notes

Ethernet switch: Connects devices on a LAN and forwards Ethernet frames.

MAC address table: Maps learned MAC addresses to switch ports (and, in actual switches, relevant VLAN information).

MAC learning: The switch learns the source MAC address from an incoming frame and associates it with the incoming port.

Known unicast: Destination MAC is in the table → forward toward the mapped port.

Unknown unicast: Destination MAC is not in the table → flood to relevant ports except the incoming port.

Broadcast: Destination MAC is FF:FF:FF:FF:FF:FF → flood within the relevant broadcast domain.

Filtering: If the destination is associated with the incoming port, the switch does not need to send the frame back through that port.

Important rule: Learn from source MAC; look up destination MAC.

MAC aging: Dynamically learned entries can eventually be removed when they become stale.
```
