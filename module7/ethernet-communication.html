MODULE 7

Ethernet Communication

Learn how devices communicate across an Ethernet network, how data is prepared for transmission, and how switches move Ethernet frames between devices.

1. What Is Ethernet Communication?

Ethernet communication is the process through which devices exchange data over a wired Local Area Network (LAN) using Ethernet technologies.

For example, imagine that PC0 wants to send information to PC1. The information does not simply jump directly from one computer to another. Several things happen before the data reaches PC1.

Simple idea

A device creates data → the data is prepared for network transmission → an Ethernet frame is created → the frame travels through the network → the switch examines it → the frame is forwarded toward the destination.

This is where the concepts we have already studied begin to connect: NICs, MAC addresses, Ethernet frames, switches, and the Data Link Layer.

2. Example: PC0 Sending Data to PC1

Consider a simple Ethernet network containing two computers connected to a switch.

PC0   →   Switch   →   PC1

Suppose PC0 needs to send some information to PC1. PC0 needs to know how to deliver the information across the local network.

At Layer 2, Ethernet uses MAC addresses to identify network interfaces on the local network.

Therefore, an Ethernet frame sent by PC0 will contain information such as:

  • The MAC address of PC1 as the destination
  • The MAC address of PC0 as the source
  • The actual data being carried
  • Error-detection information

3. How the Communication Happens

Let's break the process down into individual steps.

Step 1: The Application Creates Data

Communication normally begins with an application.

For example, you might:

  • Open a website
  • Send a message
  • Download a file
  • Send an email
  • Access a server

The application produces information that needs to be transported across the network.

At this point, we are mainly talking about the data itself. It is not yet an Ethernet frame.

Step 2: The Data Moves Through the Protocol Stack

Before the information is placed onto the physical network, networking protocols prepare it for transmission.

Different layers add the information needed for their particular responsibilities.

Step 3: The NIC Prepares the Ethernet Transmission

The computer uses its Network Interface Card (NIC) to communicate with the Ethernet network.

The NIC is the network interface that connects the computer to the network medium.

The Ethernet information is organized into a frame that can be transmitted over the network.

Step 4: The Ethernet Frame Is Sent

The NIC sends the Ethernet frame through the physical connection.

In a wired Ethernet network, this may be through a copper Ethernet cable or another supported Ethernet physical medium.

The frame reaches the switch through one of the switch's ports.

Step 5: The Switch Examines the Frame

The switch receives the frame and examines important information in the Ethernet header.

In particular, it looks at the:

  • Source MAC address
  • Destination MAC address

The switch uses these addresses to make a forwarding decision.

Step 6: The Switch Learns the Source MAC Address

When the frame enters the switch, the switch can see which port the frame came through.

For example:

PC0 → Switch Port 1

If the frame's source MAC address belongs to PC0, the switch can record something like:

PC0 MAC Address → Port 1

This information is stored in the switch's MAC address table.

Why does the switch learn the source MAC?

Because the switch knows two things at the same time:

  1. The source MAC address of the frame
  2. The port through which the frame arrived

Therefore, it can confidently associate that MAC address with that particular port.

Step 7: The Switch Checks the Destination MAC

The switch then looks at the destination MAC address.

It checks its MAC address table to determine whether it already knows which port leads to that destination.

There are several possibilities.

Case A: Destination MAC Is Known

Suppose the switch already has:

PC1 MAC Address → Port 3

If the frame is addressed to PC1, the switch forwards the frame only through Port 3.

PC0 → Switch → Port 3 → PC1

The switch does not need to send the frame to every other connected device.

Case B: Destination MAC Is Unknown

What if the switch receives a frame for a destination MAC address that is not currently in its MAC address table?

The switch cannot determine the specific port where that destination device is located.

For an unknown unicast, the switch floods the frame out the relevant ports except the port on which the frame arrived.

Important clarification

The switch does know the destination MAC address written inside the frame.

What it does not know is: which switch port currently leads to that MAC address.

Step 8: The Destination Receives the Frame

When the frame reaches the destination device, the NIC checks the frame's destination MAC address.

If the destination MAC matches the device's interface, the device accepts the frame for further processing.

The Ethernet information is then removed as the data moves upward through the networking stack.

4. Source MAC vs Destination MAC

One of the most important ideas in Ethernet switching is understanding the different jobs of the source and destination MAC addresses.

MAC Address Meaning How the Switch Uses It
Source MAC The interface that sent the frame Used to learn where that device can be reached
Destination MAC The interface the frame is intended for Used to decide where to forward the frame

Easy way to remember

Source MAC = "Where did this frame come from?"

Destination MAC = "Where should this frame go?"

5. What Happens to the Other Switch Ports?

This is an important question because a switch may have many connected devices.

If the destination MAC address is already known, the switch normally sends the frame only through the port associated with that destination.

PC0 → Switch → PC1

Other connected PCs do not receive that unicast frame.

This is one of the major reasons switches are much more efficient than old Ethernet hubs.

However, there are situations where a switch sends traffic through multiple ports.

  • Unknown unicast
  • Broadcast traffic
  • Certain multicast traffic, depending on configuration

We will examine these situations later in the module.

7. Important Terms to Understand

Term Meaning
Ethernet A family of wired LAN technologies used to communicate over local networks.
Frame The Layer 2 unit used to carry data across an Ethernet network.
NIC The network interface that allows a device to connect to a network.
MAC Address A Layer 2 address used to identify a network interface on a local Ethernet network.
Switch A Layer 2 device that receives Ethernet frames and forwards them based on MAC addresses.
MAC Address Table A table maintained by a switch that associates learned MAC addresses with switch ports.
Encapsulation The process of adding protocol information around data as it moves down the networking stack.
