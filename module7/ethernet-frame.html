MODULE 7

Ethernet Frame

Learn what an Ethernet frame is, how it is structured, what each field contains, and how the frame helps devices communicate across a local network.

1. What Is an Ethernet Frame?

An Ethernet frame is the Layer 2 unit of data used to carry information across an Ethernet network.

When a device needs to send data through an Ethernet network, the data is organized into a specific format. This format allows network devices such as switches and destination NICs to understand what the information is and where it should go.

Think of an Ethernet frame as a structured container for information.

Simple analogy: Sending a letter

Imagine that you want to send a letter to someone. You would not simply hand the receiver a random piece of paper.

You would put the letter into an envelope and provide information such as:

  • Who the letter is going to
  • Who sent it
  • The actual message
  • Information that helps the postal system handle it

Ethernet does something similar. It places data into a structured frame containing information needed for delivery and error detection.

2. Ethernet Frame Structure

A traditional Ethernet transmission contains several important parts. For this module, we will study them in the following order:

Preamble → Start Frame Delimiter → Destination MAC → Source MAC → Length/Type → Data → FCS

Each part has a different purpose.

Field Main Purpose
Preamble Helps the receiving interface synchronize with the incoming transmission.
Start Frame Delimiter (SFD) Indicates that the actual Ethernet frame is about to begin.
Destination MAC Identifies the network interface intended to receive the frame.
Source MAC Identifies the network interface that sent the frame.
Length/Type Indicates the payload length or identifies the upper-layer protocol, depending on the Ethernet framing convention.
Data Carries the information being transported.
Frame Check Sequence (FCS) Allows the receiver to detect errors in the frame.

3. Preamble

The preamble appears at the beginning of an Ethernet transmission.

Its main purpose is to help the receiving network interface synchronize with the incoming signal.

In simple terms, it gives the receiving device a predictable pattern before the actual frame information begins.

Think of it like this

Imagine someone saying: "Get ready... the message is about to start."

The preamble helps prepare the receiving interface to recognize the incoming Ethernet transmission.

The traditional Ethernet preamble is 7 bytes long.

4. Start Frame Delimiter (SFD)

Immediately after the preamble comes the Start Frame Delimiter (SFD).

The SFD indicates that the actual Ethernet frame is about to begin.

Preamble → SFD → Destination MAC → Source MAC → ...

The traditional SFD is 1 byte.

Easy way to remember

Preamble: Get synchronized and ready.

SFD: The frame starts here.

The preamble and SFD are often discussed together with Ethernet transmission, although technically they are treated somewhat differently from the MAC frame fields themselves. For this module, we will include them because they are part of the Ethernet transmission format you need to understand.

5. Destination MAC Address

The Destination MAC Address identifies the network interface that the frame is intended for.

A MAC address is normally written using hexadecimal notation. A traditional Ethernet MAC address is 48 bits, or 6 bytes.

Example:

00:1A:2B:3C:4D:5E

When a computer sends an Ethernet frame to another device on the local network, the destination MAC address is placed into the frame.

PC0 → Switch → PC1

Destination MAC = PC1's MAC address

The switch reads this field when deciding what to do with the frame.

6. Source MAC Address

The Source MAC Address identifies the network interface that sent the frame.

If PC0 sends a frame to PC1, the source MAC address in that frame is PC0's MAC address.

PC0 → Switch → PC1

Source MAC = PC0's MAC address

The source MAC address is especially important to Ethernet switches because switches use it to learn where devices are located.

Remember the difference

Source MAC: "I am the device that sent this frame."

Destination MAC: "This frame is intended for this device."

7. Length/Type Field

The field following the source MAC address is commonly called the Length/Type field.

Its meaning depends on the Ethernet framing convention being used.

Ethernet II

In Ethernet II, this field identifies the upper-layer protocol carried inside the frame. This identifier is called an EtherType.

For example, an EtherType can indicate that the payload contains an IPv4 packet or an IPv6 packet.

IEEE 802.3 Ethernet

In the IEEE 802.3 format, the field can indicate the length of the payload.

Additional mechanisms such as LLC/SNAP can then be used to identify the upper-layer protocol.

For this module

You mainly need to remember that the Length/Type field provides information about what is contained in the frame's payload.

8. Data / Payload

The Data field contains the information being transported by the Ethernet frame.

This is the part that carries the upper-layer information.

For example, the payload may contain an IP packet.

Ethernet Frame

↓

Destination MAC | Source MAC | Length/Type | IP Packet | FCS

Notice that the Ethernet frame is carrying another protocol data unit inside it.

This is one of the ideas behind encapsulation.

What if the data is very small?

Classic Ethernet has a minimum payload size requirement. If the upper-layer data is too small, padding may be added so that the Ethernet frame meets the minimum required size.

The padding is not part of the original application data. It is used to satisfy the Ethernet frame-size requirement.

9. Frame Check Sequence (FCS)

The Frame Check Sequence (FCS) is located at the end of the Ethernet frame.

It is used for error detection.

During transmission, electrical interference, damaged cables, or other problems can cause bits to change.

The FCS allows the receiving device to check whether the frame appears to have been corrupted during transmission.

Simple example

Imagine that you send someone a document and include a special value calculated from the contents of the document.

The receiver performs a similar calculation.

If the values do not match, the receiver can determine that something went wrong with the data during transmission.

Ethernet uses a form of Cyclic Redundancy Check (CRC) to generate the FCS.

Important

FCS is for detecting errors. It does not mean that Ethernet itself guarantees successful end-to-end delivery or automatically retransmits the corrupted frame.

11. Ethernet Frame as an Envelope

Let's return to our letter analogy because it makes the structure easier to remember.

Sending a Letter Ethernet
Who should receive it? Destination MAC
Who sent it? Source MAC
What is inside? Data / Payload
Information about what is inside Length/Type
Check that the message was not damaged FCS
Prepare for the beginning of transmission Preamble and SFD

The main idea

Ethernet communication works because devices agree on a common format for transmitting information.

If devices did not understand the expected frame format, they would not know how to correctly interpret the information they receive.

12. What Does a Switch Actually Read?

A switch does not need to understand the entire contents of the application data in order to perform normal Layer 2 forwarding.

It mainly needs the Ethernet information necessary to make its forwarding decision.

Ethernet Frame

↓

Destination MAC

+

Source MAC

↓

Switch makes a forwarding decision

The switch learns from the source MAC and uses the destination MAC to determine where the frame should go.

This is why understanding the Ethernet frame is essential for understanding Ethernet switches.

13. Why Frame Formatting Matters

Ethernet devices expect frames to follow the rules of the Ethernet format being used.

If a transmission is malformed or does not satisfy the required rules, the receiving equipment may be unable to process it correctly.

For example, if the frame fails its error check, the receiver can detect that the frame has been corrupted.

Think about a language

Imagine receiving a message where the words, punctuation, and structure were completely scrambled.

You might receive the information physically, but that does not mean you can correctly understand or process it.

Network devices similarly rely on agreed communication formats and rules.
