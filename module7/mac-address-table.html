MODULE 7

MAC Address Table

Learn how a switch stores MAC-to-port information, how entries are learned, how to read the MAC address table, and how to observe it in Cisco Packet Tracer.

```

1. What Is a MAC Address Table?

A MAC address table is a table maintained by an Ethernet switch that records information about MAC addresses the switch has learned and where those devices can be reached.

In its simplest form, you can think of the table as:

MAC Address → Switch Port

For example:

MAC Address Port
00:11:22:33:44:55 Fa0/1
AA:BB:CC:DD:EE:FF Fa0/2
12:34:56:78:9A:BC Fa0/3

Simple Definition

A MAC address table tells a switch which port it currently associates with a particular MAC address.

In real switches, the table also includes information such as the VLAN and the entry type. Cisco's documentation shows MAC tables containing fields such as VLAN, MAC address, type, age, and port.

2. Why Does a Switch Need This Table?

Remember that a switch can have many ports.

Suppose a switch has 24 ports and computers are connected to several of them.

When a frame arrives, the switch needs to answer:

"Which port should I use to reach the destination MAC address?"

The MAC address table provides the information needed for that Layer 2 forwarding decision.

For example:

Destination MAC: AA:BB:CC:DD:EE:FF

Table says: AA:BB:CC:DD:EE:FF → Fa0/3

Therefore: Forward the frame toward Fa0/3.

3. How Does a Switch Build the Table?

A switch does not normally require you to manually enter every device's MAC address.

It can learn MAC addresses dynamically from frames it receives.

The key rule is:

MAC Learning Rule

The switch learns the source MAC address of an incoming frame and associates it with the port where the frame arrived.

Cisco documentation describes MAC learning as associating learned addresses with interfaces, and Cisco IOS provides commands for viewing the resulting dynamic entries.

4. Example: PC0 Sends Its First Frame

Imagine this simple network:

PC0 ───── Fa0/1

         │

         SWITCH

         │

PC1 ───── Fa0/2

Suppose PC0 has this MAC address:

00:11:22:33:44:55

PC0 sends an Ethernet frame into Fa0/1.

The switch sees:

  • The frame arrived through Fa0/1.
  • The source MAC is 00:11:22:33:44:55.

Therefore the switch can create an entry:

00:11:22:33:44:55 → Fa0/1

The table now contains useful information about PC0.

5. What Does the Table Look Like Before Any Traffic?

When you first create a simple Packet Tracer network, do not assume that every connected PC will immediately appear in the switch's MAC table.

The switch learns addresses from traffic it receives.

So a connected device may not have a learned dynamic entry yet if it has not generated relevant traffic.

Important

Physical connection does not automatically mean that the switch has already learned the device's MAC address.

The switch needs to receive a frame from the device so it can learn the source MAC address.

6. What Happens After Traffic Is Sent?

Suppose PC0 sends traffic.

The switch receives the frame and learns PC0's source MAC address.

If PC1 also sends traffic, the switch can learn PC1's source MAC address too.

The table might then look like:

VLAN MAC Address Type Port
1 00:11:22:33:44:55 Dynamic Fa0/1
1 AA:BB:CC:DD:EE:FF Dynamic Fa0/2

Now the switch has information it can use for future forwarding decisions.

7. What Does "Dynamic" Mean?

When a MAC address is learned automatically from network traffic, it is commonly described as a dynamic entry.

The switch learned the information rather than having the administrator manually configure that particular entry.

Dynamic = learned automatically.

The switch can update or eventually remove dynamic information as network conditions change.

Cisco provides commands such as show mac address-table dynamic to display dynamic entries specifically.

8. What Is a Static MAC Entry?

A static MAC entry is configured rather than learned dynamically in the normal way.

An administrator can configure a MAC address and associate it with a particular VLAN and interface.

Cisco provides a mac-address-table static configuration command for static entries.

Dynamic Static
Learned from received traffic Configured by an administrator
Can age out Does not behave like a normal dynamically learned entry
Useful for normal automatic learning Useful when a specific MAC-to-port association needs to be configured

For your beginner Packet Tracer work, the most important type to understand first is the dynamic entry.

9. Why Is There a VLAN Column?

You may notice that a real Cisco MAC address table does not simply show:

MAC → Port

It commonly shows a VLAN as well.

A VLAN creates a separate Layer 2 logical network.

Therefore, the switch needs to know not only the MAC address and port, but also the Layer 2 context in which that MAC address was learned.

VLAN MAC Address Port
10 00:11:22:33:44:55 Fa0/1
20 AA:BB:CC:DD:EE:FF Fa0/2

VLANs are beyond the main focus of this page, so for now, concentrate on the basic relationship:

VLAN + MAC address + Port

10. Viewing the MAC Address Table in Cisco IOS

On a Cisco switch, the main command used to display the MAC address table is:

show mac address-table

Cisco documents this command as the command used to display the MAC address table.

You normally run this command from privileged EXEC mode, where the prompt looks similar to:

Switch#

So in Packet Tracer:

  1. Click the switch.
  2. Open the CLI tab.
  3. Make sure you are at the Switch# prompt.
  4. Type show mac address-table.
  5. Press Enter.

Do Not Confuse the Command

The command is:

show mac address-table

It is not:

show ip address-table

11. How to Read the Output

You may see output similar to:

``` 
Vlan    Mac Address       Type       Ports
----    -----------       --------   -----
1       0011.2233.4455   DYNAMIC    Fa0/1
1       aabb.ccdd.eeff   DYNAMIC    Fa0/2
```

Let's understand each column.

Column Meaning
Vlan The VLAN associated with the MAC entry.
Mac Address The learned or configured MAC address.
Type Indicates the type of entry, such as dynamic or static.
Ports The switch interface associated with the entry.

Actual output can vary by Cisco platform and IOS version, so do not worry if your Packet Tracer output is not visually identical to an example from another switch model. Cisco's documentation shows multiple forms of the command and output depending on platform.

12. Why Does Cisco Show MAC Addresses Like 0011.2233.4455?

Earlier, you learned that Ethernet MAC addresses are commonly written like:

00:11:22:33:44:55

Cisco IOS often displays the same 48-bit MAC address in groups of four hexadecimal characters:

0011.2233.4455

These represent the same hexadecimal digits.

Format Example
Colon notation 00:11:22:33:44:55
Cisco-style notation 0011.2233.4455
Hyphen notation 00-11-22-33-44-55

The notation changed, but the underlying MAC address did not.

13. Viewing Only Dynamic Entries

If the table contains many entries and you want to focus only on dynamically learned MAC addresses, Cisco IOS supports:

show mac address-table dynamic

Cisco documents this command specifically for displaying dynamic MAC address-table entries.

This is particularly useful while learning because you can focus on the addresses the switch learned automatically.

14. MAC Address Aging

Dynamic MAC entries are not necessarily stored forever.

Switches use an aging timer for dynamically learned MAC addresses.

The timer tracks how long it has been since the switch last saw traffic associated with the learned address.

If the entry becomes stale and reaches the configured aging time, it can be removed.

Cisco documentation lists 300 seconds as the default aging time for the platforms documented in its command reference, although actual defaults can vary by platform.

Why Is Aging Necessary?

Imagine:

Laptop → Port 2

Later, the laptop is moved to Port 5.

The switch needs to be able to update its information rather than permanently believing that the laptop is still reachable through Port 2.

When the laptop sends traffic from its new location, the switch can learn its source MAC on the new port.

15. Checking the Aging Time

Cisco IOS provides:

show mac address-table aging-time

This command displays the configured MAC address aging time.

In a lab, this is useful because it lets you connect the theory of aging to an actual switch configuration.

16. Can the MAC Address Table Be Cleared?

Yes.

Cisco switches provide commands for clearing MAC address-table entries. For example, Cisco documents:

clear mac-address-table dynamic

This can remove dynamically learned entries so the switch can learn them again from subsequent traffic.

For your Packet Tracer learning exercise, clearing the dynamic table can be useful because it allows you to observe the learning process from the beginning again.

17. Connecting the Table to Switching Decisions

Now connect everything from the previous page.

Situation What the Switch Does
Destination MAC is known Forward the frame toward the associated port.
Destination MAC is unknown Flood the unknown unicast to relevant ports except the incoming port.
Destination is broadcast Flood within the relevant broadcast domain.
Destination is associated with incoming port Filter rather than send the frame back out the same port.

18. One Port Can Have Multiple MAC Addresses

This is another important idea.

Do not assume:

One Port = One MAC Address

That is not always true.

For example, suppose Switch 1 connects to another switch through one port.

PC0 ──┐

PC1 ──┼── Switch 2

PC2 ──┘

       │

       │

       Port 5

       │

       Switch 1

From Switch 1's perspective, PC0, PC1, and PC2 can all be reachable through Port 5.

Therefore, the table could contain:

PC0 MAC → Port 5

PC1 MAC → Port 5

PC2 MAC → Port 5

The table tells the switch where a MAC address is reachable, not necessarily where the physical device is directly plugged into that exact switch.

19. What If a Device Moves to Another Port?

Imagine that PC0 was originally connected through Fa0/1.

The switch learned:

PC0 MAC → Fa0/1

Now suppose PC0 is physically moved and connected through Fa0/5.

When PC0 sends a new frame from Fa0/5, the switch sees its source MAC arriving through Fa0/5.

The switch can update its MAC-table information to reflect the new location.

PC0 MAC → Fa0/5

This is another reason dynamic learning is useful.

20. Packet Tracer Exercise — Watching the MAC Table Learn

This exercise is designed specifically for this module.

You have already done basic pinging and MAC-table observation in Module 1, so this exercise focuses more specifically on how the MAC table changes.

Goal

Observe how a switch learns MAC addresses from the source addresses of frames it receives.

Step 1 — Create the Topology

In Packet Tracer, create:

  • Two PCs
  • One 2960 switch

Connect:

PC0 → Switch Fa0/1

PC1 → Switch Fa0/2

Step 2 — Check the MAC Table

Open the switch CLI.

Enter:

Switch> enable

Switch# show mac address-table

Observe what appears.

Step 3 — Generate Traffic

From PC0, send traffic to PC1.

For example:

ping <PC1-IP-address>

Step 4 — Check the Table Again

Return to the switch CLI and run:

show mac address-table

Look for the MAC addresses associated with the ports.

Step 5 — Interpret What Happened

Ask yourself:

  1. Which MAC address did the switch learn first?
  2. Which port is associated with PC0?
  3. Which port is associated with PC1?
  4. Did the entries appear as dynamic?
  5. What caused the switch to learn the addresses?

The important observation is not simply that the MAC addresses appeared.

The important observation is:

A frame arrived → the switch saw its source MAC → the switch associated that MAC with the incoming port.

22. Useful Cisco Commands

Command Purpose
show mac address-table Displays the MAC address table.
show mac address-table dynamic Displays dynamically learned entries.
show mac address-table aging-time Displays the MAC address aging time.
show mac address-table vlan 1 Displays entries associated with a specified VLAN.
show mac address-table interface fa0/1 Displays entries associated with a specified interface.

Cisco documents these command variations for examining MAC address-table entries by type, VLAN, interface, address, and aging information.

24. Common Mistakes to Avoid

Mistake 1: "The switch learns the destination MAC."

Not exactly.

The switch learns from the source MAC of incoming frames.

Mistake 2: "Every port has only one MAC address."

Not necessarily. A port connecting to another switch can lead to many MAC addresses.

Mistake 3: "The table is permanent."

Dynamic entries can age out and be removed.

Mistake 4: "A connected PC must already be in the table."

Not necessarily. The switch needs to receive a frame from the device in order to learn its source MAC dynamically.

Mistake 5: "MAC address and IP address are the same."

They are different types of addresses used at different layers. MAC addresses are used for Ethernet Layer 2 communication, while IP addresses are used for logical Layer 3 communication.

25. Quick Notes

MAC address table: A switch table containing learned or configured MAC address information and associated ports/VLANs.

MAC learning: The switch learns the source MAC of an incoming frame and associates it with the incoming port.

Dynamic entry: A MAC-table entry learned automatically from traffic.

Static entry: A MAC-table entry configured by an administrator.

Known destination: The destination MAC has a table entry → forward toward the associated port.

Unknown destination: No matching MAC-table entry → flood the unknown unicast to relevant ports except the incoming port.

MAC aging: Dynamic entries can be removed after remaining unused for the configured aging period.

Main command: show mac address-table

Dynamic entries: show mac address-table dynamic

Aging time: show mac address-table aging-time

Most important rule: Learn from the source MAC; look up the destination MAC.
```
