Module 2 | Clients and Servers

Clients and Servers

So far, I have learned about network components and how devices connect to each other. Now I want to understand what actually happens when devices use a network service.

This is where the idea of clients and servers becomes important. A client requests a service, while a server provides that service.

1. What Is a Client?

A client is a device or application that requests a service or resource from another system.

The client is often the device that the user is directly interacting with.

Examples of clients include:

  • Laptop
  • Desktop computer
  • Smartphone
  • Tablet
  • Web browser
  • Email application
  • Mobile application
Simple definition:

A client is a device or application that asks another system for a service or resource.

2. What Is a Server?

A server is a system that provides a service or resource to other devices or applications.

A server can be a physical computer, a virtual machine, or software running on a computer.

Examples include:

  • Web server
  • File server
  • Database server
  • DNS server
  • DHCP server
  • Email server
  • Application server
Simple definition:

A server provides services or resources that clients can request and use.

3. The Client-Server Model

The client-server model describes a communication pattern in which a client requests something and a server responds to that request.

Client → Request → Server

Server → Response → Client

This does not mean that the client and server must be two completely different types of computers. The terms describe the roles being performed during communication.

For example, when I use a web browser to open a website, my computer is acting as a client and the web server is providing the requested website.

4. Example: Opening a Website

One of the easiest ways to understand client-server communication is to think about what happens when I open a website.

Suppose I enter a website address into my browser.

  1. I enter the website address into the browser.
  2. The client device prepares a request for the required resource.
  3. The request travels through the network.
  4. The request eventually reaches the appropriate server.
  5. The server processes the request.
  6. The server sends a response back.
  7. The browser receives the response and displays the website.

Browser → Network → Web Server

Web Server → Network → Browser

This is a simplified explanation. Many additional processes can happen during an actual web request, including DNS resolution, routing, transport connections and encryption.

5. DNS Server

DNS stands for Domain Name System.

DNS helps translate human-readable domain names into IP addresses that network devices can use to locate services.

For example, instead of having to remember the IP address of a website, I can use its domain name.

Domain name → DNS → IP address

DNS is therefore one of the important services that can be used before a client communicates with a server.

Important:

DNS does not normally deliver the website itself. Its main job is helping find the IP address associated with a domain name.

6. DHCP Server

DHCP stands for Dynamic Host Configuration Protocol.

DHCP can automatically provide network configuration information to devices when they join a network.

This can include information such as:

  • IP address
  • Subnet mask
  • Default gateway
  • DNS server information

Instead of manually configuring every computer, a DHCP server can provide network settings automatically.

This is especially useful on networks with many devices.

7. File Server

A file server provides centralized access to files and folders over a network.

For example, an organization might store shared documents on a file server so that authorized employees can access them from their computers.

Computer A → File Server ← Computer B

Instead of keeping every shared file on every computer, the organization can keep shared resources in a centralized location.

8. Database Server

A database server provides access to a database and handles requests from applications or clients that need to store or retrieve data.

For example, a university application might use a database server to store:

  • Student information
  • Course information
  • Registration records
  • Examination information
  • Financial records

A user normally does not communicate directly with the database server through a normal web browser. Instead, a client application or application server may communicate with the database.

User → Application → Database Server

9. Web Server

A web server provides web content and responds to requests from web clients such as browsers.

When I visit a website, my browser can send a request to a web server.

Browser → Request → Web Server

Web Server → Web Content → Browser

The web server may provide HTML, CSS, JavaScript, images, files or other resources required by the website.

10. How Clients and Servers Connect

A client and server still need a network connection before they can communicate.

For example:

Client Computer → Switch → Router → Network → Server

Depending on where the server is located, the path may be much shorter or much longer.

A server could be located:

  • On the same local network
  • In another building
  • In another city
  • In a data center
  • In a cloud environment

Regardless of the location, the basic idea remains: the client needs to reach the server through the network.

11. Client and Server on the Same Network

A client and server do not necessarily need to be on completely different networks.

For example, a school could have computers and a file server connected to the same local network.

Computer 1 ─┐

Computer 2 ─┼→ Switch → File Server

Computer 3 ─┘

The switch provides connectivity between the devices on the local network.

12. Client and Server Across the Internet

The client and server can also be separated by many networks.

For example, when I access a website hosted in another country, the request may travel through multiple routers and networks before reaching the server.

My Laptop → Access Point → Switch → Router → Internet → Web Server

The server then sends the response back through the network toward my device.

This connects the ideas from the previous topics: devices, connections, switches, routers and servers all work together.

13. Request and Response

The basic client-server interaction can be understood using two important words: request and response.

Request

The client asks the server to perform an action or provide information.

Response

The server processes the request and sends information or a result back to the client.

Client → Request → Server

Server → Response → Client

This simple pattern appears in many network applications.

14. One Server Can Serve Many Clients

A server can communicate with multiple clients.

Client 1 ─┐

Client 2 ─┼→ Server

Client 3 ─┤

Client 4 ─┘

For example, thousands or even millions of users can access services provided by large-scale servers and server infrastructures.

In larger environments, the workload can be distributed across multiple servers instead of relying on one physical computer.

15. Client-Server vs Peer-to-Peer

Not every network uses a dedicated central server.

Another approach is called peer-to-peer, or P2P.

In a peer-to-peer network, devices can share resources directly with one another rather than relying on a dedicated central server.

Feature Client-Server Peer-to-Peer
Main structure Centralized services Devices can share directly
Dedicated server Usually present Not required
Management More centralized More distributed
Typical use Organizations and larger networks Small or simple networks

Cisco describes client/server LANs as networks where clients connect to a central server, while peer-to-peer LANs allow devices to share resources more directly.

16. A Device Can Have Different Roles

The words "client" and "server" describe roles in a communication, not necessarily permanent identities.

A computer can act as a client when it requests a file from another computer.

The same computer could provide a service to another device and therefore act as a server in that particular communication.

Important:

Client and server describe what a device or application is doing in a particular communication.

17. Server Does Not Always Mean a Special Computer

When people hear the word "server", they often imagine a large computer sitting in a data center.

A server can certainly be a dedicated physical machine, but the term can also refer to software providing a service.

For example, web server software can run on a physical server, virtual machine or cloud infrastructure.

Server can refer to the system providing the service or to the software performing the server role, depending on the context.

18. Putting It All Together

Now I can combine the ideas from the first three topics of Module 2.

Laptop → Wi-Fi → Access Point → Ethernet → Switch → Router → Internet → Web Server

Each component has a different role:

  1. The laptop is the client.
  2. Its wireless NIC provides network connectivity.
  3. The access point provides wireless access.
  4. The switch provides local network connectivity.
  5. The router connects the local network to other networks.
  6. The Internet provides connectivity across many networks.
  7. The web server provides the requested web service.

This is the point where the different networking concepts begin to connect together.

19. What to Remember

  • A client requests a service or resource.
  • A server provides a service or resource.
  • Client-server communication commonly follows a request-and-response pattern.
  • Web browsers and web servers are a common example of the client-server model.
  • DNS helps clients find the IP address associated with domain names.
  • DHCP can automatically provide network configuration information to clients.
  • Servers can provide many different services, including web, file, database, DNS and email services.
  • A client and server can be on the same local network or separated by many networks.
  • A server can communicate with many clients.
  • Client and server describe roles in communication rather than necessarily describing permanent device types.
