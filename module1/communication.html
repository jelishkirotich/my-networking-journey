1. The parts of communication

Communication is the exchange of information between two or more parties. In a network the parties are devices: computers, phones, printers, servers, switches and routers.

  • Sender: the device that starts the exchange.
  • Receiver: the device the message is meant for.
  • Message: the information being sent.
  • Medium: the path it travels on, such as a cable or radio waves.
  • Protocols: the rules both sides follow.
A cable between two devices is not enough. They also need addresses, compatible settings, a shared protocol and a usable path.

Two PCs in the same lab talk through a switch. A PC reaching a website on another network needs a router as well. Your home router usually combines a router, a switch and an access point in one box.

3. How data travels

Data does not cross a network as one large lump. It is split up and prepared, and each layer adds its own information, called a header, so the next device knows how to handle it. This is called encapsulation.

If PC0 is 192.168.1.10 and PC1 is 192.168.1.20 with subnet mask 255.255.255.0, they are on the same IPv4 network.

5. Protocols

A protocol is a set of rules for communicating. Without shared rules, devices from different makers could not understand each other.

6. ICMP and ping

Ping sends an ICMP echo request to a destination. If the destination is reachable and allowed to answer, it sends back an echo reply.

PC0 --echo request--> PC1 PC0 <--echo reply---- PC1

A successful ping is good evidence that the path works. A failed ping does not always mean a broken cable. A firewall, a wrong setting, a routing problem or disabled ICMP replies can cause it too.

7. ARP

PC0 knows PC1 has the IP address 192.168.1.20, but the Ethernet frame needs a MAC address. PC0 asks the whole local network: who has 192.168.1.20? That question is an ARP request and it is broadcast. The owner replies with its MAC address in an ARP reply.

PC0 --ARP request (broadcast)--> everyone on the LAN PC0 <--ARP reply (MAC address)--- PC1
ARP does not replace IP. It links an IPv4 address to a MAC address on the local network.

8. Switching

A switch keeps a MAC address table: each MAC address it has learned and the port it was learned on.

  • Learning: when a frame arrives, the switch records the source MAC address against the arrival port.
  • Known destination: the frame is sent out of the matching port only.
  • Unknown destination: the frame is flooded out of every port except the one it came in on. The reply then teaches the switch the missing address.

10. Quick check

Which device connects different networks?

A router, using IP addresses.

Why does a device need both an IP and a MAC address?

The IP address finds the destination across networks. The MAC address delivers the frame inside the local network.

What does ARP do?

It finds the MAC address that belongs to a known IPv4 address on the local network.

What does a switch do with a frame whose destination it does not know?

It floods it out of every port except the one it arrived on.

Does a failed ping always mean the cable is broken?

No. Firewalls, settings, routing or disabled ICMP replies can also cause it.
