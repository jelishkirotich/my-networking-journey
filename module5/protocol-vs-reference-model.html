MODULE 5

Protocol Models and Reference Models

Understanding how network protocols are organized, how protocol models differ from reference models, and how TCP/IP and OSI help us understand communication between networked devices.

Introduction

We have already learned that communication between computers does not happen using one single protocol. A message may need several different protocols before it can travel from one device to another.

For example, when you open a website, protocols such as HTTP or HTTPS, TCP, IP, and Ethernet or Wi-Fi may all be involved in delivering the information.

This raises an important question:

How do we organize all these protocols so that we can understand what each one does?

Network engineers use models to organize and explain network communication. Two important types are:

  • Protocol models
  • Reference models

The two types of models are related, but they are not the same thing.

1. What Is a Network Model?

A network model is a way of organizing the different tasks involved in network communication into understandable groups or layers.

Network communication is actually very complicated. A computer needs to deal with applications, data formatting, reliability, addressing, routing, hardware addresses, cables, wireless signals, and many other things.

Instead of trying to understand everything at once, we divide the communication process into layers.

Each layer has a specific responsibility.

This makes networking easier to design, troubleshoot, learn, and understand.

A Simple Example

Imagine sending a physical letter.

Several different things must happen:

  1. You write the message.
  2. The message is placed inside an envelope.
  3. The destination address is written on the envelope.
  4. The postal service transports it.
  5. The recipient receives the letter.
  6. The recipient opens the envelope and reads the message.

Computer networking works in a similar way. Different parts of the communication process have different responsibilities.

2. What Is a Protocol Model?

A protocol model is a model that describes how actual networking protocols work together and how their functions are organized into layers.

In other words, it is closely connected to real protocols that are actually used to communicate across networks.

The TCP/IP model is commonly used as an example of a protocol model because it is associated with the actual protocols used by the Internet.

These include protocols such as:

  • HTTP and HTTPS
  • DNS
  • DHCP
  • TCP
  • UDP
  • IP
  • Ethernet
  • Wi-Fi

These protocols do different jobs, but they cooperate to allow communication to happen.

3. The TCP/IP Protocol Model

The TCP/IP model is commonly represented using four layers.

04

Application

Provides network services used by applications. Examples include HTTP, DNS, DHCP and SMTP.

03

Transport

Provides communication between applications. Main protocols include TCP and UDP.

02

Internet

Handles logical addressing and routing using IP.

01

Network Access

Handles local network delivery and the physical transmission of data using technologies such as Ethernet and Wi-Fi.

The important thing to understand is that these layers are not independent.

They work together.

4. What Is a Reference Model?

A reference model is a conceptual framework used to describe and understand how different functions of network communication should be organized.

It does not necessarily represent the exact protocols being used on the Internet.

Instead, it gives us a common way of thinking about networking.

The best-known example is the OSI Reference Model.

OSI divides network communication into seven layers:

  1. Application
  2. Presentation
  3. Session
  4. Transport
  5. Network
  6. Data Link
  7. Physical

Each layer describes a different group of networking functions.

5. Why Was the OSI Model Created?

Before standardized networking approaches became widespread, different manufacturers could develop networking systems that worked differently.

This could make communication between different systems difficult.

The OSI model provided a common framework for describing network communication.

This allowed engineers and students to talk about networking functions using the same language.

For example, if someone says:

"This problem is occurring at Layer 2."

They are referring to the Data Link layer and functions such as MAC addressing, frames, and local network communication.

If someone says:

"This is a Layer 3 problem."

They are referring to the Network layer, where IP addressing and routing are important.

6. TCP/IP Model vs OSI Reference Model

TCP/IP and OSI both use layers, but they were created for different purposes and do not have exactly the same number of layers.

TCP/IP

Commonly represented using four layers and closely associated with the protocols used by the Internet.

OSI

Uses seven layers and provides a detailed conceptual framework for understanding network functions.

Layer Mapping

The layers can be approximately mapped like this:

OSI Layers 7, 6 and 5 → TCP/IP Application Layer

OSI Layer 4 → TCP/IP Transport Layer

OSI Layer 3 → TCP/IP Internet Layer

OSI Layers 2 and 1 → TCP/IP Network Access Layer

Notice something important: TCP/IP combines some functions that OSI separates into different layers.

For example, OSI has separate Presentation and Session layers, while the TCP/IP model generally places those functions within the Application layer.

7. Why Does One Message Need Multiple Protocols?

This is one of the most important ideas in networking.

A single protocol cannot perform every job required to successfully deliver information across a network.

Different protocols solve different problems.

Example: Opening a Website

Suppose you type a website address into your browser.

Several protocols may become involved.

  1. DNS can translate the website name into an IP address.
  2. HTTP or HTTPS defines how the web request and response are communicated.
  3. TCP can provide reliable transport for the application data when TCP is used.
  4. IP provides logical addressing and allows routers to forward packets toward the destination.
  5. Ethernet or Wi-Fi can carry the data across the local network.

Each protocol has its own responsibility.

They cooperate rather than competing with each other.

8. Think of the Protocols as Different Jobs

A useful way to understand this is to imagine several people working together to deliver a package.

One person may write the contents. Another may package it. Another may put the destination address on it. Another may transport it. Another may deliver it to the correct building.

No single person has to perform every task.

Networking protocols work in a similar way.

HTTP

Defines how web information is requested and transferred.

TCP

Provides reliable, ordered transport when an application uses TCP.

IP

Provides logical addressing and routing between networks.

Ethernet

Provides communication across a wired local network.

Wi-Fi

Provides wireless local network communication.

9. How the Protocols Work Together: Encapsulation

When data is sent, each layer can add information needed for its particular job.

This process is called encapsulation.

A simplified example looks like this:

Application data

↓

TCP adds transport information

↓

IP adds logical addressing information

↓

Ethernet or Wi-Fi adds local delivery information

↓

Data is transmitted as signals/bits

This is why we can have different pieces of information associated with the same communication.

TCP is concerned with transport. IP is concerned with logical addressing and routing. Ethernet or Wi-Fi is concerned with local network delivery.

They are solving different problems for the same communication.

10. What Happens at the Receiving Device?

The receiving device performs the opposite process.

This is called decapsulation.

The receiving device processes the information layer by layer.

Signals/bits

↓

Ethernet or Wi-Fi information is processed

↓

IP information is processed

↓

TCP or UDP information is processed

↓

Application receives the data

The destination device can therefore understand the original application data.

11. What Is a Protocol Suite?

A protocol suite is a collection of related protocols that work together to provide network communication.

TCP/IP is not just TCP.

This is an important distinction.

TCP is one transport protocol.

IP is a network-layer protocol.

TCP/IP refers to the broader collection of protocols and technologies associated with the Internet protocol architecture.

Other protocols in this family include HTTP, DNS, DHCP, UDP and many others.

12. Protocols and Standards

Protocols need agreed rules so that devices made by different manufacturers can communicate.

These rules can specify things such as:

  • How messages are formatted
  • How large messages can be
  • How devices identify each other
  • How data is transmitted
  • How errors are handled
  • How communication begins and ends
  • How devices know when data has arrived

Standards help different networking devices and software follow compatible rules.

This is one reason you can connect a phone from one manufacturer to a Wi-Fi router from another manufacturer and communicate successfully.

13. Why Models Are Useful for Troubleshooting

Network models are also useful when diagnosing problems.

Instead of treating a network problem as one huge problem, we can examine the different layers.

Example

Imagine a computer cannot access a website.

We can ask different questions:

  • Is the physical cable connected?
  • Is the network interface working?
  • Does the device have a valid IP address?
  • Can it reach the gateway?
  • Is DNS working?
  • Is the transport connection working?
  • Is the web service available?

These questions correspond to different networking functions and layers.

This makes troubleshooting more organized.

14. The Big Picture

At this point, you should understand the relationship between protocols, protocol models, and reference models.

Protocol = A set of rules used for a particular type of communication.

Protocol suite = A collection of protocols that work together.

Protocol model = A way of organizing and describing how real protocols work together.

Reference model = A conceptual framework used to describe networking functions.

TCP/IP = The protocol architecture associated with the Internet and commonly represented using four layers.

OSI = A seven-layer reference model used to understand and describe network communication.

Module Summary

Network communication is too complex to understand as one single process, so networking functions are organized into layers.

A protocol model is closely connected to the organization of actual networking protocols, while a reference model provides a conceptual framework for understanding those functions.

The TCP/IP model is commonly represented using four layers, while the OSI reference model contains seven layers.

The two models can be mapped to each other, but they are not identical.

Most importantly, a single message requires multiple protocols because different protocols perform different jobs. HTTP may handle web communication, TCP may provide reliable transport, IP handles logical addressing and routing, and Ethernet or Wi-Fi can provide local network delivery.

Understanding this relationship is essential before moving deeper into how actual network communication takes place.
