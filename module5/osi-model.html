OSI Reference Model

Understanding the seven layers of the OSI reference model and how each layer contributes to network communication.

What Is the OSI Model?

OSI stands for Open Systems Interconnection. The OSI model is a seven-layer reference model used to help us understand how network communication is organized.

Network communication involves many different functions. Data must be created, formatted, transported, addressed, delivered across local networks, and transmitted through a physical medium. Trying to understand all of these processes as one large process would be difficult.

The OSI model divides these networking functions into seven layers. Each layer has a specific responsibility and works with the layers above and below it.

The seven layers, from the top down, are:

Application → Presentation → Session → Transport → Network → Data Link → Physical

The Seven OSI Layers

7

Application

Provides network services used by applications and application-level protocols.

6

Presentation

Deals with data representation, formatting, encryption, decryption, compression, and decompression.

5

Session

Establishes, manages, synchronizes, and terminates communication sessions.

4

Transport

Provides end-to-end communication between applications, including segmentation, reliability, and flow control.

3

Network

Provides logical addressing and routing between different networks.

2

Data Link

Provides local network delivery using frames, MAC addresses, and link-layer technologies.

1

Physical

Transmits bits as physical signals through copper, fiber-optic, or wireless media.

Layer 7: Application

The Application layer is Layer 7 and is the highest layer of the OSI model. It provides network services that applications use when they need to communicate across a network.

An important point is that the Application layer is not simply the application itself. Instead, it represents the network services and application-level protocols that applications use.

Examples of application-level protocols and services include HTTP, HTTPS, DNS, SMTP, FTP, and DHCP.

For example, when you open a website, your browser communicates with a web server using an application-level protocol such as HTTP or HTTPS.

Examples at the Application Layer

HTTP

Web Communication

Defines communication used by web clients and web servers to request and transfer web resources.

DNS

Name Resolution

Helps translate domain names into IP addresses that systems can use for network communication.

DHCP

Network Configuration

Can automatically provide devices with network configuration information such as IP addresses.

SMTP

Email Communication

Used for sending email between mail systems.

Layer 6: Presentation

The Presentation layer is Layer 6. It is concerned with how information is represented so that communicating systems can interpret the data correctly.

The layer can be associated with functions such as data formatting, character encoding, encryption, decryption, compression, and decompression.

Think of this layer as dealing with the way information is represented rather than with the network route that the information takes.

Presentation Layer Functions

01

Data Formatting

Organizes information into a representation that the receiving system can interpret.

02

Encoding

Represents information using an agreed encoding scheme so that it can be interpreted correctly.

03

Encryption

Information can be transformed into a protected form that requires appropriate decryption to be understood.

04

Compression

Data can be compressed to reduce the amount of information that needs to be transmitted or stored.

Layer 5: Session

The Session layer is Layer 5. It is concerned with establishing, managing, synchronizing, and terminating communication sessions between applications.

A session can be thought of as an organized period of communication between two systems or applications.

Conceptually, a session can follow a process such as:

Session starts → communication takes place → session ends

The Session layer can also provide mechanisms for synchronization and coordination during communication.

In modern TCP/IP networking, these responsibilities are often handled by applications and protocols rather than by a separate Session layer.

Layer 4: Transport

The Transport layer is Layer 4 and is one of the most important layers when studying network communication.

It provides communication between applications running on different devices. It can be responsible for segmentation, reassembly, reliability, flow control, error recovery, and identifying applications using port numbers.

Two important transport protocols are TCP and UDP.

TCP and UDP

TCP

Transmission Control Protocol

Provides connection-oriented communication and mechanisms for reliable and ordered delivery, including sequencing, acknowledgements, retransmission, and flow control.

UDP

User Datagram Protocol

Provides a simpler connectionless transport service without TCP's reliability and ordering mechanisms.

TCP Reliability

TCP is designed to provide reliable, ordered delivery of data between communicating applications.

TCP uses mechanisms such as sequence numbers and acknowledgements to keep track of transmitted data. If data needs to be retransmitted, TCP can send it again.

TCP also provides flow control so that a sender does not overwhelm a receiver with more data than it can handle.

Conceptually, communication can look like this:

Data sent → Receiver acknowledges → Missing data detected → Data retransmitted

Port Numbers

A computer can run many network applications at the same time. An IP address identifies a network endpoint, but another mechanism is needed to identify the particular application or service involved in a communication.

Transport protocols use port numbers for this purpose.

A useful simplified way to think about this is:

IP address = Which network endpoint?
Port number = Which application or service?

The actual identification of a communication endpoint can involve an IP address together with a transport protocol and port number.

Layer 3: Network

The Network layer is Layer 3. Its major responsibilities include logical addressing and routing packets between different networks.

The Internet Protocol, or IP, is the major protocol associated with this layer. IP includes IPv4 and IPv6.

Unlike local delivery, which happens within a particular network, the Network layer allows packets to travel between interconnected networks.

IP and Routing

IP

Logical Addressing

IP provides logical addressing information used to identify network endpoints and support communication between networks.

IPv4

32-Bit Addresses

IPv4 uses 32-bit addresses and remains widely deployed in networks around the world.

IPv6

128-Bit Addresses

IPv6 uses 128-bit addresses and provides a much larger address space than IPv4.

Routing

Moving Between Networks

Routers use network-layer information to make forwarding decisions and move packets toward their destinations.

Packets

At the Network layer, the data is commonly referred to as a packet.

When a transport-layer segment is passed to IP, IP adds its own information, including source and destination addressing information, creating an IP packet.

Conceptually:

Application data → TCP segment → IP packet

Layer 2: Data Link

The Data Link layer is Layer 2. It is concerned primarily with communication across a local network link.

This layer deals with technologies such as Ethernet and Wi-Fi and includes functions involving frames, local addressing, media access, and error detection mechanisms provided by particular link technologies.

This layer connects directly to concepts studied in earlier modules, including MAC addresses, switches, Ethernet, and wireless networking.

MAC Addresses and Frames

MAC

Local Addressing

Ethernet and other link technologies use MAC addressing for local network communication.

Frames

Data Link Unit

At the Data Link layer, network-layer packets can be carried inside frames for transmission across a local link.

Switch

Local Forwarding

Ethernet switches use MAC address information to make forwarding decisions within a local network.

Ethernet

Wired LAN Technology

Ethernet provides technologies for communication across wired local area networks.

Layer 1: Physical

The Physical layer is Layer 1 and is the lowest layer of the OSI model. It is concerned with the actual transmission of bits across a physical medium.

The physical medium can include copper cables, fiber-optic cables, or wireless radio signals.

At this level, digital information is represented as physical signals that can travel through the selected medium.

Physical Transmission

01

Copper

Electrical signals can be used to represent and transmit digital information through copper cables.

02

Fiber Optic

Fiber-optic communication uses light to transmit information through optical fiber.

03

Wireless

Wireless technologies use radio signals to transmit information without a physical cable between devices.

04

Bits

Digital information is ultimately represented as sequences of bits that are transmitted as physical signals.

How the Seven Layers Work Together

The seven layers should not be thought of as completely separate systems. They work together to move information from an application on the sending device to an application on the receiving device.

Each layer has its own responsibilities and provides services to the layer above it. The information moves down the layers on the sender and up the layers on the receiver.

A simplified view is:

Application → Presentation → Session → Transport → Network → Data Link → Physical

Following Data Through the OSI Model

Imagine that a device is sending information to another device. The application first creates the data that needs to be communicated.

At the Presentation layer, the information may be formatted, encoded, compressed, or encrypted depending on the protocols being used.

The Session layer can manage the communication session. The Transport layer then handles end-to-end transport and can divide the information into smaller units.

The Network layer adds logical addressing information and allows packets to be routed toward the destination.

The Data Link layer prepares the packet for local transmission using a technology such as Ethernet or Wi-Fi.

Finally, the Physical layer transmits the resulting information as physical signals.

Data Units at Different Layers

As information moves through the lower layers, different terms are commonly used to describe the resulting units of data.

Application data
↓
Transport segment
↓
Network packet
↓
Data Link frame
↓
Physical bits

These names help network engineers identify which stage of communication they are discussing.

Encapsulation

When data moves down the networking layers, each layer can add information needed to perform its function. This process is called encapsulation.

For example, transport information can be added to application data. Network-layer information can then be added, followed by Data Link information needed for local transmission.

A simplified representation is:

Data → Segment → Packet → Frame → Bits

Decapsulation

When the information reaches the receiving device, the process happens in the opposite direction.

The receiving device processes the physical signals, interprets the Data Link frame, processes the Network-layer packet, handles the Transport-layer information, and eventually delivers the application data to the appropriate application.

This reverse process is called decapsulation.

Conceptually:

Bits → Frame → Packet → Segment → Application Data

OSI and the TCP/IP Model

The OSI model has seven layers, while the commonly used four-layer TCP/IP model has four layers.

The models organize networking functions differently. The OSI model separates Application, Presentation, and Session functions into three layers, while the TCP/IP model generally combines these functions into its Application layer.

Similarly, the OSI Data Link and Physical layers are generally represented together as the Network Access layer in the four-layer TCP/IP model.

OSI to TCP/IP Mapping

OSI 7–5

Application, Presentation, Session

These three OSI layers are broadly represented by the Application layer in the four-layer TCP/IP model.

OSI 4

Transport

The OSI Transport layer corresponds broadly to the Transport layer in TCP/IP.

OSI 3

Network

The OSI Network layer corresponds broadly to the Internet layer in TCP/IP.

OSI 2–1

Data Link and Physical

These two OSI layers are broadly represented by the Network Access layer in the four-layer TCP/IP model.

Key Idea

The OSI model is a framework for understanding network communication by dividing the process into seven layers. Each layer has a particular responsibility, from providing application services at Layer 7 to transmitting physical signals at Layer 1.

The most important thing is not simply memorizing the seven names. You should understand how the layers cooperate to move data from one application to another.

The OSI model also provides a useful way to understand networking technologies you have already studied. HTTP and other application protocols relate to the upper layers, TCP and UDP operate at the Transport layer, IP operates at the Network layer, Ethernet and MAC addressing relate to the Data Link layer, and physical media operate at the Physical layer.

The next step is to understand why the OSI model and TCP/IP model are organized differently and what is meant by a protocol model versus a reference model.
