Encapsulation and Decapsulation

Understanding how data is prepared, wrapped with control information, transmitted across a network, and processed by the receiving device.

Introduction

When one computer sends information to another computer, the original data does not simply travel across the network exactly as it was created.

The data passes through different networking layers. Each layer has a particular responsibility and may add information that is needed for communication.

This process is called encapsulation.

When the receiving device processes the information and removes the information added by the different layers, the reverse process is called decapsulation.

Understanding these two processes helps us understand what actually happens to a message as it travels through a network.

1. What Is Encapsulation?

Encapsulation is the process of adding control information to data as it moves through the networking layers.

Each layer receives information from the layer above it and adds information required for its own job.

Think about sending a physical letter.

You first write your message. Then you place it inside an envelope. You write the destination address on the envelope. The postal system then uses that information to deliver the letter.

Computer networking works in a similar way.

The original application data is gradually wrapped with additional networking information.

The important idea is:

Data is passed down through the layers, and each layer adds information needed for communication.

2. Why Is Encapsulation Necessary?

Different layers have different responsibilities.

For example, an application does not need to know how an Ethernet frame is physically transmitted over a cable.

Similarly, a network interface does not need to understand what the web page inside the data means.

Each layer focuses on its own job.

Information added by one layer allows that layer's corresponding process at the destination to understand what to do with the data.

For example:

  • TCP adds transport information such as source and destination ports and sequence information.
  • IP adds logical addressing information.
  • Ethernet adds information needed for local network delivery.
  • The Physical layer converts the resulting information into signals that can travel through the transmission medium.

3. Data Units at Different Layers

As data moves through the networking layers, the resulting units are commonly given different names.

Data

At the upper layers, the information is generally referred to as data or a message.

Segment

When TCP is used at the Transport layer, the data is commonly called a segment.

Packet

At the Network layer, the unit is commonly called a packet.

Frame

At the Data Link layer, the unit is commonly called a frame.

Bits

At the Physical layer, the information is transmitted as bits represented by physical signals.

Therefore, a simplified way of remembering the process is:

Data → Segment → Packet → Frame → Bits

This naming is a useful way of identifying what stage of communication we are talking about.

4. What Are Headers?

A header is control information added to the beginning of data by a protocol.

The header contains information that the receiving device or another networking device may need.

Different protocols add different types of information.

Example: TCP Header

A TCP header can contain information such as:

  • Source port
  • Destination port
  • Sequence number
  • Acknowledgement information
  • Control flags
  • Window information

This information helps TCP perform its transport responsibilities.

Example: IP Header

An IP header contains information associated with network-layer delivery.

Important information includes the source and destination IP addresses.

Routers use the destination IP address when making forwarding decisions.

5. What Are Trailers?

Some protocols also add information to the end of the data. This is called a trailer.

Ethernet frames, for example, can contain a trailer used for error detection.

The trailer helps the receiving device determine whether the frame was corrupted during transmission.

Therefore, encapsulation does not always mean simply adding information to the beginning.

Depending on the protocol, information may be added as a header, a trailer, or both.

6. Encapsulation Step by Step

Let's follow a simple example where a computer sends information to a web server.

Step 1: Application Data

The process begins with the application.

For example, you may enter a website address into a browser and the browser creates a request for the web server.

At this point, we can simply think of the information as application data.

Step 2: Transport Layer

The data moves to the Transport layer.

If TCP is being used, TCP adds its own header.

The result is commonly called a TCP segment.

TCP Header + Application Data

= TCP Segment

Step 3: Network Layer

The segment is passed to the Network layer.

IP adds an IP header containing information such as the source and destination IP addresses.

The result is commonly called an IP packet.

IP Header + TCP Segment

= IP Packet

Step 4: Data Link Layer

The packet is passed to the Data Link layer.

A technology such as Ethernet or Wi-Fi adds the information required for local network delivery.

The result is called a frame.

Ethernet/Wi-Fi Header + IP Packet + Frame Trailer

= Frame

Step 5: Physical Layer

Finally, the frame is converted into signals that can travel through the physical medium.

Depending on the technology, this could involve electrical signals, light pulses, or radio waves.

At this stage, we commonly refer to the information as bits.

7. The Complete Encapsulation Flow

The complete process can be simplified as follows:

Application

Application Data

↓

Transport

TCP Header + Data

↓

Network

IP Header + TCP Segment

↓

Data Link

Frame Header + IP Packet + Frame Trailer

↓

Physical

Bits / Signals

Remember that this is a simplified representation. Actual protocol details can be more complex, and not every application uses TCP.

8. What Is Decapsulation?

Decapsulation is the reverse of encapsulation.

It occurs as the receiving device processes the incoming information and removes or processes the headers and trailers associated with the different layers.

The information moves upward through the layers until the original application data is delivered to the appropriate application.

The simplified process is:

Bits → Frame → Packet → Segment → Data

9. Decapsulation Step by Step

Step 1: Physical Layer

The receiving device first receives physical signals through the network medium.

The signals are interpreted as bits.

Step 2: Data Link Layer

The Data Link layer processes the incoming frame.

It examines information such as the local destination MAC address and performs the appropriate frame processing.

The Data Link information is then processed so that the IP packet inside can be passed upward.

Step 3: Network Layer

The Network layer processes the IP packet.

The destination IP address identifies the logical destination of the communication.

The IP information is processed and the transport-layer information is passed upward.

Step 4: Transport Layer

If TCP is being used, TCP processes the segment.

TCP can use information such as port numbers, sequence numbers, acknowledgements, and other control information to provide the transport service required by the application.

Once processed, the application data is passed upward.

Step 5: Application

The application finally receives the information.

For example, a web browser may receive information that it can use to display a web page.

10. Encapsulation vs Decapsulation

Encapsulation

Happens as data moves down the layers on the sending device.

Information is added by the different protocols and layers.

Direction:

Application → Physical

Decapsulation

Happens as the receiving device processes the incoming information.

The information added for the communication is processed and removed as appropriate.

Direction:

Physical → Application

11. A Very Important Idea: Peer-to-Peer Communication

When we say that TCP works at the Transport layer, we can imagine that TCP on the sending device communicates with TCP on the receiving device.

Similarly, IP on the sending device and IP on the receiving device follow the rules of the IP protocol.

However, the actual data does not physically jump from the Transport layer of one computer directly to the Transport layer of another computer.

Instead, the information moves down through the sender's layers, travels across the network, and then moves up through the receiver's layers.

The idea of peer-to-peer communication means that corresponding layers follow the rules defined by the same protocol.

12. What Happens When a Router Receives the Packet?

An important question is whether every device removes every layer of encapsulation.

No.

Different network devices operate at different layers.

A router primarily makes forwarding decisions using Network-layer information such as IP addresses.

When a router receives an Ethernet frame, it processes the frame, examines the IP packet inside, makes a routing decision, and then creates a new Data Link frame for the next network segment.

This means the Layer 2 frame can change as the packet travels from one network to another.

The IP packet, however, is designed to travel across multiple networks toward its destination, although some IP header fields can change along the way.

13. Complete Example: Opening a Website

Let's put everything together.

Imagine your laptop is connected to a Wi-Fi router and you open a website.

At Your Laptop

  1. The browser creates application data.
  2. The Transport layer processes the communication using TCP when TCP is being used.
  3. IP adds logical addressing information.
  4. Wi-Fi creates a wireless frame for local delivery.
  5. The Physical layer transmits the information using radio signals.

At the Router

  1. The router receives the wireless frame.
  2. It processes the Data Link information.
  3. It examines the IP packet.
  4. It determines where the packet should go next.
  5. It sends the packet using the appropriate outgoing network technology.

At the Web Server

  1. The server receives the transmitted information.
  2. The information is processed upward through the networking layers.
  3. Transport-layer information is processed.
  4. The application receives the original request.
  5. The web server processes the request and sends a response.

14. The Most Important Thing to Remember

Encapsulation is not simply "adding random information to data."

Each layer adds information for a specific networking purpose.

Application data is created by an application.

TCP can add transport information.

IP adds logical addressing information.

Ethernet or Wi-Fi adds local delivery information.

Physical networking converts the information into signals.

At the destination, the receiving device processes this information in the opposite direction until the original application data can be used.

Module Summary

Encapsulation is the process in which data moves down through the networking layers and receives additional control information from different protocols.

A simplified sequence is:

Data → Segment → Packet → Frame → Bits

The Transport layer can add information such as TCP or UDP details. The Network layer can add IP addressing information. The Data Link layer can add local delivery information, and the Physical layer transmits the resulting information as signals.

Decapsulation is the reverse process:

Bits → Frame → Packet → Segment → Data

Understanding encapsulation and decapsulation makes it much easier to understand what happens to data as it travels through a network.

It also explains why several protocols can work together to deliver one message. Each protocol contributes a different part of the communication process.
